# Bevy

> Bevy is a refreshingly simple, data-driven game engine built in Rust. It uses an Entity Component System (ECS) architecture and a modular plugin-based design. Bevy targets native (Windows, macOS, Linux) and WebAssembly. Current version: 0.18.0.

Bevy applications are built by composing **Plugins** into an `App`. The engine ships two plugin bundles: `DefaultPlugins` (full 2D/3D/UI engine) and `MinimalPlugins` (bare essentials). Each Bevy module maps to a `bevy_*` crate on crates.io, re-exported through the top-level `bevy` crate.

Core architecture concepts:
- **Entities** are unique identifiers (lightweight `Entity` IDs, not objects)
- **Components** are plain Rust structs (`#[derive(Component)]`) stored on entities
- **Resources** are singleton data types accessed via `Res<T>` / `ResMut<T>`
- **Systems** are plain functions whose parameter types determine data access; the scheduler auto-parallelizes non-conflicting systems
- **Queries** (`Query<&Transform, With<Player>>`) retrieve component data with type-safe filters (`With`, `Without`, `Added`, `Changed`)
- **Commands** queue structural changes (spawn, despawn, insert/remove components) applied at the next `ApplyDeferred` sync point
- **Observers** are push-based event handlers triggered immediately when matching events fire
- **Messages** are pull-based inter-system communication via `MessageWriter<T>` / `MessageReader<T>`
- **Schedules** execute systems in dependency order: `Startup`, `PreUpdate`, `Update`, `PostUpdate`, `FixedUpdate`
- **States** are finite state machines (`States` trait) with `OnEnter`/`OnExit` transition schedules and `DespawnOnExit` for scoped entities

The `prelude` module re-exports the most commonly used types. When in doubt about where a type lives, check the prelude first.

Important: Bevy 0.18 changed `despawn_recursive()` to just `despawn()` — it is recursive by default now. Calling the old method will not compile.

## Getting Started

### Minimal App

```rust
use bevy::prelude::*;

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_systems(Startup, setup)
        .add_systems(Update, my_system)
        .run();
}

fn setup(mut commands: Commands) {
    // Spawn a 2D camera
    commands.spawn(Camera2d);
}

fn my_system() {
    // Runs every frame
}
```

### Adding Dependencies

```toml
# Cargo.toml
[dependencies]
bevy = "0.18"

# For faster compile times during development:
[profile.dev]
opt-level = 1
[profile.dev.package."*"]
opt-level = 3
```

### Feature Flags

Bevy uses Cargo features to control what gets compiled. Key feature groups:

- `default` — includes 2D, 3D, UI, audio, and platform defaults
- `2d` — 2D sprites, text, and rendering
- `3d` — 3D meshes, PBR, lighting, and shadows
- `ui` — ECS-driven UI framework
- `audio` — Audio playback
- `dev_tools` — Screenshot capture, screen recording, diagnostics

Disable defaults and pick only what you need for smaller binaries:

```toml
bevy = { version = "0.18", default-features = false, features = ["3d", "ui"] }
```

## Core Concepts and Syntax

### Components

Components are data types stored on entities. Derive `Component` to make any struct or enum a component.

```rust
use bevy::prelude::*;

// Basic component
#[derive(Component)]
struct Health(f32);

// Component with named fields
#[derive(Component)]
struct Player {
    name: String,
    speed: f32,
}

// Marker component (no data, used for query filtering)
#[derive(Component)]
struct Enemy;

// Component with SparseSet storage (faster insert/remove, slower iteration)
#[derive(Component)]
#[component(storage = "SparseSet")]
struct IsRunning;

// Component with lifecycle hooks
#[derive(Component)]
#[component(on_add = on_health_added)]
struct Armor(f32);

fn on_health_added(trigger: On<OnAdd>, query: Query<&Armor>) {
    let armor = query.get(trigger.target()).unwrap();
    info!("Armor added: {}", armor.0);
}

// Required components: spawning Player automatically inserts Transform and Health
#[derive(Component)]
#[require(Transform, Health(|| Health(100.0)))]
struct Warrior;
```

**Storage types:**
- `Table` (default): Components stored in contiguous arrays. Fast iteration, slower insert/remove.
- `SparseSet`: Components stored in a sparse set. Fast insert/remove, slower iteration. Use for components that are frequently added/removed.

### Resources

Resources are global singleton data, not tied to any entity.

```rust
use bevy::prelude::*;

#[derive(Resource)]
struct Score(u32);

#[derive(Resource, Default)]
struct GameSettings {
    difficulty: f32,
    volume: f32,
}

// Insert resources on app startup
fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .insert_resource(Score(0))
        .init_resource::<GameSettings>() // uses Default::default()
        .add_systems(Update, update_score)
        .run();
}

// Access resources in systems
fn update_score(mut score: ResMut<Score>, settings: Res<GameSettings>) {
    score.0 += 1;
    info!("Score: {}, Difficulty: {}", score.0, settings.difficulty);
}
```

### Systems

Systems are plain Rust functions. Their parameter types declare what data they access. The scheduler uses this to auto-parallelize.

```rust
use bevy::prelude::*;

// System with no parameters
fn hello_world() {
    info!("Hello world!");
}

// System reading components
fn print_positions(query: Query<(&Transform, &Name)>) {
    for (transform, name) in &query {
        info!("{}: {:?}", name, transform.translation);
    }
}

// System with multiple parameters
fn combat_system(
    mut commands: Commands,
    time: Res<Time>,
    mut query: Query<(Entity, &mut Health, &Transform), With<Enemy>>,
) {
    for (entity, mut health, transform) in &mut query {
        health.0 -= 10.0 * time.delta_secs();
        if health.0 <= 0.0 {
            commands.entity(entity).despawn();
        }
    }
}
```

### System Registration and Ordering

```rust
use bevy::prelude::*;

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        // Run once at startup
        .add_systems(Startup, setup)
        // Run every frame
        .add_systems(Update, (
            move_player,
            check_collisions.after(move_player),
            update_ui.after(check_collisions),
        ))
        // Chain: A -> B -> C (runs sequentially, with ApplyDeferred between each)
        .add_systems(Update, (spawn_enemies, position_enemies, activate_enemies).chain())
        // Run in FixedUpdate (fixed timestep, default 64 Hz)
        .add_systems(FixedUpdate, physics_step)
        .run();
}
```

### System Sets

Group systems and apply shared ordering/conditions.

```rust
use bevy::prelude::*;

#[derive(SystemSet, Debug, Clone, PartialEq, Eq, Hash)]
enum GameSet {
    Input,
    Movement,
    Collision,
}

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .configure_sets(Update, (
            GameSet::Input,
            GameSet::Movement.after(GameSet::Input),
            GameSet::Collision.after(GameSet::Movement),
        ))
        .add_systems(Update, (
            read_input.in_set(GameSet::Input),
            move_player.in_set(GameSet::Movement),
            move_enemies.in_set(GameSet::Movement),
            check_collisions.in_set(GameSet::Collision),
        ))
        .run();
}
```

### Run Conditions

Conditionally enable/disable systems at runtime.

```rust
use bevy::prelude::*;

#[derive(States, Debug, Clone, PartialEq, Eq, Hash, Default)]
enum GameState {
    #[default]
    Menu,
    Playing,
    Paused,
}

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .init_state::<GameState>()
        .add_systems(Update, (
            // Only runs when GameState is Playing
            player_movement.run_if(in_state(GameState::Playing)),
            // Only runs when a resource changed
            update_ui.run_if(resource_changed::<Score>),
            // Custom run condition
            spawn_wave.run_if(wave_timer_finished),
        ))
        .run();
}

fn wave_timer_finished(time: Res<Time>) -> bool {
    // Custom condition logic
    time.elapsed_secs() > 30.0
}
```

### Queries

Queries retrieve component data from entities. The first type parameter is the data to fetch, the optional second is a filter.

```rust
use bevy::prelude::*;

#[derive(Component)]
struct Health(f32);
#[derive(Component)]
struct Speed(f32);
#[derive(Component)]
struct Player;
#[derive(Component)]
struct Enemy;

// Read-only query
fn read_health(query: Query<&Health>) {
    for health in &query {
        info!("Health: {}", health.0);
    }
}

// Mutable query
fn heal_all(mut query: Query<&mut Health>) {
    for mut health in &mut query {
        health.0 += 1.0;
    }
}

// Query with filter
fn enemy_positions(query: Query<&Transform, With<Enemy>>) {
    for transform in &query {
        info!("Enemy at: {:?}", transform.translation);
    }
}

// Multiple filters
fn fast_enemies(query: Query<(&Speed, &Transform), (With<Enemy>, Without<Player>)>) {
    for (speed, transform) in &query {
        if speed.0 > 10.0 {
            info!("Fast enemy at {:?}", transform.translation);
        }
    }
}

// Optional components
fn show_names(query: Query<(Entity, Option<&Name>)>) {
    for (entity, name) in &query {
        match name {
            Some(n) => info!("{entity}: {n}"),
            None => info!("{entity}: unnamed"),
        }
    }
}

// Single entity query (panics if not exactly one match)
fn player_system(player: Single<&Transform, With<Player>>) {
    info!("Player at: {:?}", player.translation);
}

// Change detection
fn on_health_changed(query: Query<(Entity, &Health), Changed<Health>>) {
    for (entity, health) in &query {
        info!("{entity} health changed to {}", health.0);
    }
}

// Newly added components
fn on_enemy_spawned(query: Query<Entity, Added<Enemy>>) {
    for entity in &query {
        info!("New enemy spawned: {entity}");
    }
}
```

### Commands

Commands queue deferred structural changes. They are applied at the next `ApplyDeferred` sync point (automatically inserted between system sets, and between chained systems).

```rust
use bevy::prelude::*;

#[derive(Component)]
struct Health(f32);
#[derive(Component)]
struct Player;
#[derive(Component)]
struct Enemy;
#[derive(Component)]
struct Damage(f32);

fn spawn_player(mut commands: Commands) {
    commands.spawn((
        Player,
        Health(100.0),
        Transform::from_xyz(0.0, 0.0, 0.0),
        Name::new("Hero"),
    ));
}

fn spawn_enemies(mut commands: Commands) {
    for i in 0..10 {
        commands.spawn((
            Enemy,
            Health(50.0),
            Transform::from_xyz(i as f32 * 2.0, 0.0, 0.0),
        ));
    }
}

fn add_component(mut commands: Commands, query: Query<Entity, (With<Player>, Without<Damage>)>) {
    for entity in &query {
        commands.entity(entity).insert(Damage(25.0));
    }
}

fn remove_component(mut commands: Commands, query: Query<Entity, With<Damage>>) {
    for entity in &query {
        commands.entity(entity).remove::<Damage>();
    }
}

fn despawn_dead(mut commands: Commands, query: Query<(Entity, &Health)>) {
    for (entity, health) in &query {
        if health.0 <= 0.0 {
            commands.entity(entity).despawn(); // recursive by default in 0.18
        }
    }
}
```

### Entity Hierarchies (Parent-Child)

Bevy uses `ChildOf` relationship components. The `children![]` macro is the idiomatic way to spawn hierarchies.

```rust
use bevy::prelude::*;

fn spawn_hierarchy(mut commands: Commands) {
    // Spawn parent with children using the children! macro
    commands.spawn((
        Transform::default(),
        Visibility::default(),
        Name::new("Parent"),
        children![
            (
                Transform::from_xyz(1.0, 0.0, 0.0),
                Name::new("Child A"),
                children![
                    (Transform::from_xyz(0.0, 1.0, 0.0), Name::new("Grandchild")),
                ],
            ),
            (Transform::from_xyz(-1.0, 0.0, 0.0), Name::new("Child B")),
        ],
    ));
}

// Query children
fn iterate_children(
    parents: Query<&Children>,
    names: Query<&Name>,
) {
    for children in &parents {
        for &child in children.iter() {
            if let Ok(name) = names.get(child) {
                info!("Child: {name}");
            }
        }
    }
}

// Query parent
fn find_parent(
    query: Query<(&Name, &ChildOf)>,
    names: Query<&Name>,
) {
    for (name, child_of) in &query {
        let parent = child_of.parent();
        if let Ok(parent_name) = names.get(parent) {
            info!("{name} is child of {parent_name}");
        }
    }
}
```

### Events and Observers

Observers are push-based: they run immediately when their event fires. Use them for entity lifecycle hooks, one-shot reactions, and decoupled communication.

```rust
use bevy::prelude::*;

// Define a custom event
#[derive(Event)]
struct PlayerDied {
    entity: Entity,
    position: Vec3,
}

// Trigger events from systems
fn check_death(
    mut commands: Commands,
    query: Query<(Entity, &Health, &Transform)>,
) {
    for (entity, health, transform) in &query {
        if health.0 <= 0.0 {
            commands.trigger(PlayerDied {
                entity,
                position: transform.translation,
            });
        }
    }
}

// Register observers on app setup
fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_observer(on_player_died)
        .run();
}

// Observer system — runs immediately when PlayerDied is triggered
fn on_player_died(trigger: On<PlayerDied>, mut commands: Commands) {
    info!("Player died at {:?}", trigger.position);
    commands.entity(trigger.entity).despawn();
}
```

**Entity-targeted events** fire on a specific entity and bubble up through the hierarchy:

```rust
use bevy::prelude::*;

#[derive(Event)]
struct Clicked;

fn setup(mut commands: Commands) {
    commands.spawn((
        Name::new("Button"),
        // Attach an observer to this specific entity
        Observer::new(|_trigger: On<Clicked>| {
            info!("Button clicked!");
        }),
    ));
}
```

### Messages (Pull-Based Communication)

Messages are the pull-based alternative to observers. Systems write messages; other systems read them on the next tick.

```rust
use bevy::prelude::*;

#[derive(Event)]
struct DamageEvent {
    target: Entity,
    amount: f32,
}

fn deal_damage(mut writer: MessageWriter<DamageEvent>) {
    // Write messages for other systems to read
    writer.write(DamageEvent {
        target: Entity::PLACEHOLDER,
        amount: 10.0,
    });
}

fn apply_damage(
    mut reader: MessageReader<DamageEvent>,
    mut query: Query<&mut Health>,
) {
    for event in reader.read() {
        if let Ok(mut health) = query.get_mut(event.target) {
            health.0 -= event.amount;
        }
    }
}

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_event::<DamageEvent>() // Register the message type
        .add_systems(Update, (deal_damage, apply_damage).chain())
        .run();
}
```

### States

States control large-scale program flow: menus, gameplay, pausing.

```rust
use bevy::prelude::*;

#[derive(States, Debug, Clone, PartialEq, Eq, Hash, Default)]
enum AppState {
    #[default]
    Loading,
    Menu,
    InGame,
}

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .init_state::<AppState>()
        // Systems that run once on state entry/exit
        .add_systems(OnEnter(AppState::Menu), setup_menu)
        .add_systems(OnExit(AppState::Menu), cleanup_menu)
        .add_systems(OnEnter(AppState::InGame), setup_game)
        // Systems that run every frame while in a state
        .add_systems(Update, menu_input.run_if(in_state(AppState::Menu)))
        .add_systems(Update, game_logic.run_if(in_state(AppState::InGame)))
        .run();
}

// Change state using NextState resource
fn menu_input(
    keyboard: Res<ButtonInput<KeyCode>>,
    mut next_state: ResMut<NextState<AppState>>,
) {
    if keyboard.just_pressed(KeyCode::Enter) {
        next_state.set(AppState::InGame);
    }
}

// Automatically despawn entities when leaving a state
fn setup_menu(mut commands: Commands) {
    commands.spawn((
        Node::default(),
        DespawnOnExit(AppState::Menu), // auto-cleanup on state exit
    ));
}
```

**SubStates** depend on parent states and are automatically removed when the parent condition isn't met:

```rust
use bevy::prelude::*;

#[derive(SubStates, Debug, Clone, PartialEq, Eq, Hash, Default)]
#[source(AppState = AppState::InGame)] // only exists when InGame
enum GamePhase {
    #[default]
    Explore,
    Combat,
    Dialogue,
}
```

### Transforms

Every visible entity needs a `Transform`. Bevy auto-propagates transforms through hierarchies into `GlobalTransform`.

```rust
use bevy::prelude::*;

fn spawn_entities(mut commands: Commands) {
    // Transform has translation, rotation, and scale
    commands.spawn(Transform::from_xyz(10.0, 5.0, 0.0));

    // Rotation
    commands.spawn(
        Transform::from_xyz(0.0, 0.0, 0.0)
            .with_rotation(Quat::from_rotation_y(std::f32::consts::FRAC_PI_4)),
    );

    // Scale
    commands.spawn(Transform::from_scale(Vec3::splat(2.0)));

    // Looking at a target
    commands.spawn(Transform::from_xyz(5.0, 5.0, 5.0).looking_at(Vec3::ZERO, Vec3::Y));
}

// Move entities each frame
fn movement(mut query: Query<&mut Transform, With<Player>>, time: Res<Time>) {
    for mut transform in &mut query {
        transform.translation.x += 5.0 * time.delta_secs();
        transform.rotate_y(1.0 * time.delta_secs());
    }
}

// Read world-space transform (computed from hierarchy)
fn world_position(query: Query<&GlobalTransform, With<Player>>) {
    for global in &query {
        let world_pos = global.translation();
        info!("World position: {world_pos}");
    }
}
```

## Custom Shaders

### Material Trait

Implement `Material` for custom shader materials. Derive `AsBindGroup` for automatic bind group layout.

```rust
use bevy::prelude::*;
use bevy::render::render_resource::{AsBindGroup, ShaderRef};

#[derive(Asset, AsBindGroup, Debug, Clone, TypePath)]
struct CustomMaterial {
    #[uniform(0)]
    color: LinearRgba,
    #[uniform(0)]
    time: f32,
    #[texture(1)]
    #[sampler(2)]
    color_texture: Handle<Image>,
}

impl Material for CustomMaterial {
    fn fragment_shader() -> ShaderRef {
        "shaders/custom_material.wgsl".into()
    }
    fn alpha_mode(&self) -> AlphaMode {
        AlphaMode::Blend
    }
}

fn main() {
    App::new()
        .add_plugins((DefaultPlugins, MaterialPlugin::<CustomMaterial>::default()))
        .add_systems(Startup, setup)
        .run();
}

fn setup(
    mut commands: Commands,
    mut meshes: ResMut<Assets<Mesh>>,
    mut materials: ResMut<Assets<CustomMaterial>>,
    asset_server: Res<AssetServer>,
) {
    commands.spawn((
        Mesh3d(meshes.add(Sphere::new(1.0))),
        MeshMaterial3d(materials.add(CustomMaterial {
            color: LinearRgba::new(1.0, 0.0, 0.5, 1.0),
            time: 0.0,
            color_texture: asset_server.load("textures/pattern.png"),
        })),
    ));
}
```

## Color

Bevy supports 10 color spaces. All color structs convert into each other via `From`/`Into`. `Oklch` is recommended for perceptual mixing.

```rust
use bevy::prelude::*;
use bevy::color::palettes::css;

fn color_examples() {
    // sRGB (web colors)
    let red = Color::srgb(1.0, 0.0, 0.0);
    let transparent_blue = Color::srgba(0.0, 0.0, 1.0, 0.5);

    // From hex
    let coral = Srgba::hex("FF7F50").unwrap();

    // Named CSS colors
    let tomato = Color::from(css::TOMATO);
    let gold = Color::from(css::GOLD);

    // Linear RGB (for shaders/GPU)
    let linear = Color::linear_rgb(0.5, 0.5, 0.5);

    // HSL (hue/saturation/lightness)
    let hsl = Color::hsl(120.0, 1.0, 0.5); // pure green

    // Oklab (perceptually uniform — best for mixing)
    let warm = Oklcha::new(0.7, 0.15, 30.0, 1.0);
    let cool = Oklcha::new(0.7, 0.15, 250.0, 1.0);

    // Color operations via traits (Luminance, Alpha work on Srgba directly)
    let lighter = css::TOMATO.lighter(0.2);
    let darker = css::TOMATO.darker(0.3);
    let faded = css::TOMATO.with_alpha(0.5);

    // Hue rotation requires a hue-bearing space (Hsla, Oklcha, etc.)
    let as_hsl: Hsla = css::TOMATO.into();
    let rotated = as_hsl.with_hue(180.0);

    // Perceptual mixing (works best in Oklch)
    let mixed = warm.mix(&cool, 0.5);
}
```

## Curves and Easing

The `Curve<T>` trait represents continuous values over a parameter range. Combinators compose curves without allocating.

```rust
use bevy::prelude::*;

fn curve_examples() {
    // Function curve — any closure over a domain
    let sine = FunctionCurve::new(
        interval(0.0, std::f32::consts::TAU).unwrap(),
        |t| Vec3::new(t.cos(), t.sin(), 0.0),
    );

    // Constant curve
    let flat = ConstantCurve::new(interval(0.0, 1.0).unwrap(), Vec3::ZERO);

    // Easing curve (0.0 -> 1.0 with easing function)
    let ease = EasingCurve::new(0.0, 1.0, EaseFunction::CubicInOut);

    // Combinators
    let reversed = sine.reverse().unwrap();
    let looped = sine.repeat(3).unwrap();
    let bounced = sine.ping_pong().unwrap();
    let forever = sine.forever().unwrap();
    let mapped = sine.map(|v| v * 2.0);
    let chained = sine.chain(flat).unwrap();

    // Sample a curve
    let value = sine.sample(1.0);          // Option<Vec3>
    let clamped = sine.sample_clamped(5.0); // clamps t to domain
}
```

`EaseFunction` has 39 variants: `Linear`, `QuadraticIn/Out/InOut`, `CubicIn/Out/InOut`, `QuarticIn/Out/InOut`, `QuinticIn/Out/InOut`, `SineIn/Out/InOut`, `CircularIn/Out/InOut`, `ExponentialIn/Out/InOut`, `ElasticIn/Out/InOut`, `BackIn/Out/InOut`, `BounceIn/Out/InOut`, `SmoothStep`, `SmootherStep`, `Steps(n, JumpAt)`.

## Common Pitfalls

- **Forgetting `mut`**: `Query<&Transform>` is read-only. Use `Query<&mut Transform>` for mutation.
- **Query conflicts**: Two `Query` parameters in the same system cannot access the same component mutably. Use `ParamSet` when you need overlapping mutable access.
- **Commands are deferred**: `commands.spawn(...)` doesn't take effect until the next `ApplyDeferred` point. Don't try to query for just-spawned entities in the same system.
- **Transform vs GlobalTransform**: Modify `Transform` (local). Read `GlobalTransform` (world-space, computed by Bevy). Never write to `GlobalTransform` directly.
- **Asset paths**: Paths are relative to the `assets/` directory. Use forward slashes even on Windows. glTF sub-assets use `#` syntax: `"model.glb#Scene0"`, `"model.glb#Animation0"`.
- **Change detection is per-tick**: `Changed<T>` fires the tick after mutation, not the exact frame. In `Startup`, all components report as `Added`.
- **System ordering**: Without explicit ordering, systems in the same set may run in any order. Use `.before()`, `.after()`, or `.chain()` when order matters.
- **FixedUpdate vs Update**: Physics and gameplay logic that should be deterministic belongs in `FixedUpdate`. Rendering and input in `Update`. `FixedUpdate` may run 0, 1, or multiple times per frame.
- **Web/WASM**: Audio requires SharedArrayBuffer headers (COOP/COEP). Some features are unavailable on WASM (filesystem, threads without atomics).
- **`Single<>` panics**: `Single<&T, With<Player>>` panics if there isn't exactly one matching entity. Use `Option<Single<...>>` or a regular `Query` if the entity might not exist.

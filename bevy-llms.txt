# Bevy

> Bevy is a modular, data-driven game engine built in Rust. It uses an Entity Component System (ECS) architecture where game objects are entities composed of data components, transformed by systems that run on schedules. Bevy supports 2D and 3D rendering, audio, input, UI, animation, physics integration, asset loading, scenes, and cross-platform deployment including WebAssembly. Current version: 0.18.

Bevy applications are built with `App`, which configures resources, systems, and plugins, then enters the event loop. `DefaultPlugins` provides a standard set (rendering, input, windowing, audio). `MinimalPlugins` gives a headless baseline. Each Bevy module maps to a `bevy_*` crate, re-exported through the top-level `bevy` crate.

**ECS fundamentals.** An `Entity` is a lightweight ID. A `Component` is data attached to an entity via `#[derive(Component)]`. Components have storage types: `Table` (default, cache-friendly iteration) or `SparseSet` (fast insert/remove). Required components let one component automatically pull in others: `#[require(Transform, Visibility)]`. Component hooks (`on_add`, `on_insert`, `on_remove`, `on_replace`, `on_despawn`) fire on lifecycle changes. A `Resource` is global singleton data accessed via `Res<T>` (read) or `ResMut<T>` (write).

**Systems and queries.** Systems are plain functions whose parameter types determine data access; the scheduler auto-parallelizes non-conflicting systems. `Query<&Transform>` iterates all entities with `Transform`. Filters narrow results: `With<T>`, `Without<T>`, `Added<T>`, `Changed<T>`. `Single` asserts exactly one match. `Populated` asserts at least one. `ParamSet` resolves conflicting query access within one system. `Local<T>` gives per-system persistent state.

**Commands.** `Commands` queues deferred structural changes applied at the next sync point: `commands.spawn(bundle)`, `commands.entity(id).insert(component)`, `commands.entity(id).remove::<T>()`, `commands.entity(id).despawn()`. In 0.18, `despawn()` is recursive by default -- `despawn_recursive()` is removed. Use `despawn_self()` for entity-only removal. `get_components_mut()` provides safe mutable access to multiple components on one entity.

**Spawning and hierarchies.** Entities are created by spawning bundles -- tuples of components: `commands.spawn((Transform::default(), Mesh3d(mesh), MeshMaterial3d(material)))`. The `ChildOf` component establishes parent-child relationships; `Children` is a read-only view. `with_child()`, `with_children()`, and the `children![]` macro build hierarchies.

**Schedules and ordering.** Systems run in schedules: `Startup` (once), `PreUpdate`, `Update`, `PostUpdate`, `FixedPreUpdate`, `FixedUpdate` (fixed timestep), `FixedPostUpdate`. Order within a schedule is controlled by `SystemSet` and ordering constraints: `.before()`, `.after()`, `.in_set()`, `.chain()`. Run conditions gate execution: `.run_if(in_state(GameState::Playing))`, `.run_if(resource_exists::<Config>)`, `.run_if(resource_changed::<Score>)`.

**Observers and messages.** Observers react to entity-level events immediately: `commands.add_observer(|trigger: On<MyEvent>, ...| { ... })`. Trigger with `commands.trigger(event)` or `commands.trigger_targets(event, entity)`. Entity-targeted events bubble up through hierarchies. For pull-based system-to-system communication, `MessageWriter<T>` sends and `MessageReader<T>` receives typed messages within a schedule. Messages require `add_event::<T>()` registration.

**States.** `States` are enum-based app modes. Transition with `NextState::set()`. `OnEnter(state)` and `OnExit(state)` schedules run on transitions. `SubStates` depend on parent states and are removed when the parent condition isn't met. `ComputedStates` derive automatically from other states. `DespawnOnExit` and `DespawnOnEnter` marker components auto-cleanup entities on state transitions.

**Assets.** `AssetServer` loads files asynchronously: `asset_server.load("texture.png")` returns a `Handle<T>` immediately. `Assets<T>` stores loaded asset data. `AssetLoader` trait defines custom formats. `AssetEvent<T>` notifies on load/modify/remove. Paths are relative to the `assets/` directory. glTF sub-assets use `#` syntax: `"model.glb#Scene0"`.

**Transforms.** `Transform` holds local translation (`Vec3`), rotation (`Quat`), and scale (`Vec3`). `GlobalTransform` is the computed world-space transform, propagated automatically through hierarchies in `PostUpdate`. Always write `Transform`, read `GlobalTransform`.

**3D rendering.** A visible 3D object needs `Mesh3d`, `MeshMaterial3d<StandardMaterial>`, and `Transform`. `StandardMaterial` covers PBR: `base_color`, `metallic`, `perceptual_roughness`, `emissive`, `alpha_mode` (Opaque, Blend, Mask, Add, Multiply, AlphaToCoverage), `unlit`, `double_sided`, `normal_map_texture`, `reflectance`. Custom shaders implement the `Material` trait. `MaterialExtension` extends `StandardMaterial` via `ExtendedMaterial<StandardMaterial, MyExtension>`. `FullscreenMaterial` (new in 0.18) is a trait for fullscreen post-processing shader materials.

**Lighting.** `DirectionalLight` (sun), `PointLight` (omni), `SpotLight` (cone), `AmbientLight` (flat fill), `EnvironmentMapLight` (IBL via HDR cubemaps). `ShadowFilteringMethod` controls shadow quality. Cascaded shadow maps on directional lights.

**Camera.** `Camera3d` and `Camera2d` are the primary camera markers. `PerspectiveProjection` and `OrthographicProjection` control the view. `RenderLayers` assigns cameras and objects to specific render passes. 0.18 adds first-party controllers: `FreeCamera` (fly-cam with WASD + mouse look) and `PanCamera` (orbit/pan).

**Post-processing and anti-aliasing.** `Bloom` (glow from bright areas), `DepthOfField` (Bokeh or Gaussian modes), `ChromaticAberration`, `ColorGrading` (exposure, contrast, saturation per tonal range). Anti-aliasing: `Msaa` (multisample), `Fxaa` (fast approximate), `TemporalAntiAliasing` (TAA). Fog: `DistanceFog` with `FogFalloff` variants (Linear, Exponential, ExponentialSquared, Atmospheric), plus `VolumetricFog` for volumetric light shafts.

**PBR advanced.** `ScreenSpaceAmbientOcclusion` (SSAO), `ScreenSpaceReflections` (SSR), decals for projected detail, light probes for baked indirect lighting. The `solari` module provides raytraced global illumination on supported hardware.

**Meshes.** `Mesh` holds vertex data via `MeshVertexAttribute` (positions, normals, UVs, tangents). Built-in primitives: `Cuboid`, `Sphere`, `Plane3d`, `Cylinder`, `Capsule3d`, `Torus`, `Circle`, `Rectangle`, `Triangle2d`, `Annulus`, `ConicalFrustum`. Create meshes from primitives: `Mesh::from(Sphere::new(1.0))`.

**2D rendering.** `Sprite` renders images with `Anchor` positioning. `TextureSlicer` for 9-slice scaling. `SpriteScalingMode` and `SpriteImageMode` control fill behavior. `Text2d` renders world-space text. `Mesh2d` with `MeshMaterial2d<ColorMaterial>` for 2D shapes.

**UI.** Bevy UI uses flexbox and CSS Grid layout via the `Node` component. Key properties: `Display` (Flex/Grid/Block/None), `FlexDirection`, `JustifyContent`, `AlignItems`, `Val` (Px/Percent/Auto/Vw/Vh), `Overflow` with `OverflowClipMargin`, `ZIndex`, `ScrollPosition`. Styling: `BackgroundColor`, `BorderColor`, `BorderRadius`, `LinearGradient`, `RadialGradient`, `ConicGradient`. Grid: `GridTrack`, `GridPlacement`, `GridAutoFlow`. `Interaction` component tracks hover/press state. 0.18 adds `AutoDirectionalNavigation` for gamepad/keyboard UI navigation.

**Widgets.** `Button`, `Checkbox`, `Slider`, `RadioButton`, `RadioGroup`. 0.18 adds `Popover` and `MenuPopup`. The `feathers` module provides styled, themed widgets for editor/inspector UIs.

**Text.** `Text` for UI text, `Text2d` for world-space text. `TextFont` sets family, size, style. `TextColor` sets color. `TextLayout` controls alignment and wrapping. `LineHeight` adjusts spacing. 0.18 adds `Strikethrough`, `Underline`, `FontSmoothing`, and font variation support.

**Picking.** `Pickable` makes entities interactive with pointer events: `Pointer<Click>`, `Pointer<Over>`, `Pointer<Out>`, `Pointer<Move>`, `Pointer<Drag>`, `Pointer<DragStart>`, `Pointer<DragEnd>`, `Pointer<DragDrop>`. Events bubble up entity hierarchies. `MeshRayCast` for manual ray queries. Works for both UI and 3D entities.

**Input.** `ButtonInput<KeyCode>` for keyboard, `ButtonInput<MouseButton>` for mouse, `ButtonInput<GamepadButton>` for gamepads. Methods: `pressed()`, `just_pressed()`, `just_released()`. `Gamepad` component for connected controllers with axis queries. `MouseWheel`, `MouseMotion` events. `TouchInput` and `Touches` for touchscreens. Gesture events: `PinchGesture`, `RotationGesture`, `PanGesture`, `DoubleTapGesture`. The `input_focus` module provides a UI-centric focus system. The `gilrs` module handles advanced gamepad features.

**Animation.** `AnimationPlayer` drives playback on entities. `AnimationClip` stores keyframe data. `AnimationGraph` defines blend trees and state machines, attached via `AnimationGraphHandle`. `AnimationTargetId` identifies animated bones/nodes. `AnimationEvent` triggers gameplay logic at specific keyframes. `RepeatAnimation` controls looping (Never, Count, Forever).

**Audio.** `AudioPlayer` component triggers playback. `AudioSink` controls playing sounds (pause, resume, stop, volume). `SpatialAudioSink` adds 3D positioning. `PlaybackSettings` configures mode (Once, Loop, Despawn), volume, speed, spatial. `GlobalVolume` sets master volume. `SpatialListener` marks the hearing entity.

**Scenes.** `Scene` is a static entity snapshot. `DynamicScene` is serializable via reflection. `DynamicSceneBuilder` constructs scenes from world state. `SceneRoot` and `DynamicSceneRoot` components spawn scenes as hierarchies. `SceneSpawner` manages instantiation. `SceneInstanceReady` event fires when spawning completes.

**glTF.** Loads `.gltf`/`.glb` files. `Gltf` is the top-level asset containing `GltfNode`, `GltfMesh`, `GltfPrimitive`, `GltfSkin` sub-assets. Label syntax: `"model.glb#Scene0"`, `"model.glb#Mesh0/Primitive0"`. 0.18 adds `GltfExtensionHandler` for custom glTF extension processing.

**Math.** `Vec2`, `Vec3`, `Vec3A`, `Vec4`, `Mat3`, `Mat4`, `Quat` (re-exported from glam). `Rot2` for 2D rotations. `Dir2`, `Dir3` for normalized directions. `Isometry2d`, `Isometry3d` for rigid transforms. Geometric primitives for intersection/distance queries.

**Color.** `Color` enum supports 10 color spaces: `Srgba`, `LinearRgba`, `Hsla`, `Hsva`, `Hwba`, `Laba`, `Lcha`, `Oklaba`, `Oklcha`, `Xyza`. Trait-based operations: `Alpha` (opacity), `Luminance` (lighten/darken), `Hue` (shift/rotate), `Mix` (interpolate).

**Curves.** `Curve<T>` trait represents continuous mappings. `CurveExt` provides combinators: `map`, `chain`, `reverse`, `repeat`, `forever`, `ping_pong`, `zip`, `graph`. `EaseFunction` has 39 easing variants. Concrete types: `FunctionCurve`, `ConstantCurve`, `SampleCurve`.

**Time.** `Time` resource gives delta and elapsed time. `Time<Fixed>` for fixed timestep. `Time<Real>` for wall-clock. `Timer` (Once/Repeating) counts down. `Stopwatch` counts up.

**Window.** `Window` component configures title, resolution, mode, vsync. `WindowPlugin` in `DefaultPlugins`. `Monitor` for physical displays. `CursorGrabMode` (None/Confined/Locked). `ExitCondition` controls app exit. `WindowLevel` for always-on-top.

**Reflection.** `Reflect` enables runtime type introspection. `#[derive(Reflect)]` on types, `#[reflect(Component)]` for ECS integration. `FromReflect` converts dynamic values to concrete types. `TypeRegistry` stores metadata. `ReflectComponent` and `ReflectResource` allow dynamic ECS access. Used by scenes, inspectors, and the remote protocol.

**Gizmos.** `Gizmos` system parameter draws debug shapes: `line`, `ray`, `circle`, `sphere`, `cuboid`, `arrow`, `arc_2d`, `grid`, `axes`. `GizmoConfigGroup` customizes appearance. `gizmos_render` handles the rendering backend.

**Dev tools.** `EasyScreenshotPlugin` and `EasyScreenRecordPlugin` for captures (new in 0.18). `FpsOverlayConfig` for frame rate display. `CiTestingPlugin` for automated testing.

**Remote.** `RemotePlugin` enables the Bevy Remote Protocol for external tool communication. `RemoteHttpPlugin` serves on port 15702 by default.

**Diagnostics.** `FrameTimeDiagnosticsPlugin`, `EntityCountDiagnosticsPlugin`, `LogDiagnosticsPlugin` for monitoring. Custom diagnostics via the `Diagnostic` type.

**Cargo feature collections.** Bevy 0.18 defaults to `["2d", "3d", "ui"]`. Use `default-features = false` with specific profiles for minimal builds: `bevy = { version = "0.18", default-features = false, features = ["3d"] }`. The `dynamic_linking` feature speeds up recompilation during development. The `dev` feature enables hot-reloading and debugging tools.

## Common Pitfalls

- `despawn()` is recursive by default in 0.18. `despawn_recursive()` is removed. Use `despawn_self()` for entity-only removal without children.
- Systems accessing the same component mutably in the same schedule will panic unless ordering constraints or `ParamSet` resolve the conflict.
- `Transform` propagation runs in `PostUpdate`. Systems modifying transforms that expect children to reflect changes must run before `TransformSystems::Propagate`.
- Assets load asynchronously. A `Handle<T>` is not ready immediately -- check `AssetEvent::LoadedWithDependencies` or poll `AssetServer::is_loaded_with_dependencies()`.
- `FixedUpdate` runs at a fixed timestep, which may execute 0, 1, or multiple times per frame. Use `Time<Fixed>::delta()` in `FixedUpdate`, not `Time::delta()`.
- WASM builds require careful feature gating. Not all plugins work on web (multi-threaded task pools, some audio backends). Audio requires SharedArrayBuffer headers (COOP/COEP).
- `Interaction` only works on UI nodes with `Node`. For 3D entity interaction, use the `picking` module with `Pickable`.
- `Changed<T>` and `Added<T>` detect changes since the last run of that system, not since the previous frame. They may miss changes if checked from a different schedule.
- Forgetting `#[derive(Component)]` or `#[derive(Resource)]` produces confusing trait-bound errors, not a clear "missing derive" message.
- `Single` panics if zero or multiple entities match. Use `Option<Single<...>>` for fallible access.
- Nested hierarchies add transform propagation cost. Keep hierarchies shallow where possible.
- Hot reloading requires the asset watcher feature. Set `BEVY_ASSET_ROOT` when the working directory differs from the project root.
- `SpatialListener` is required on an entity (typically the camera) for spatial audio to work. Without it, spatial sources are silent.
- `Commands` are deferred. `commands.spawn()` does not take effect until the next `ApplyDeferred` sync point. Do not query for just-spawned entities in the same system.
- Always write `Transform` (local), read `GlobalTransform` (world-space). Never write `GlobalTransform` directly.
